## 1. 概要

Issue #79 の対応。全データベースの日次ダンプを OCI Object Storage へ退避し、失敗時にメールで通知する。
設計は [MySQL詳細設計書 4.2](../03.detailed-design/MySQL詳細設計書.md#42-バックアップ) を参照する。

## 2. 前提条件

- [03 構築手順書](03_Ansibleによるサーバ構成管理.md) の内容が完了していること
- Terraform Cloud のワークスペース変数 `notification_email`（通知先メールアドレス）を設定していること

## 3. 手順

### 3.1. Terraform でクラウド側リソースを作成する

```bash
~/.claude/scripts/tf_plan.sh
```

```bash
~/.claude/scripts/tf_apply.sh
```

- 1つ目で、Object Storage バケット・ライフサイクルルール・通知トピックと購読・IAM ポリシー・
  Vault Secret `backup-dbuser-password` の作成内容を確認する
- 2つ目で、確認した内容を適用する

### 3.2. 通知メールの購読を確認する

OCI から通知先メールアドレスへ届く確認メールのリンクを開き、購読を有効にする。
リンクを開くまで、購読は保留状態のままで通知は届かない。

### 3.3. Ansible でバックアップ機構を構成する

```bash
./scripts/run_ansible.sh --tags mysql,backup --check
```

```bash
./scripts/run_ansible.sh --tags mysql,backup
```

- 1つ目で、変更されるタスクを確認する
- 2つ目で、MySQL ユーザー `backup-dbuser` の作成と、`backup` ロール（OCI CLI・ダンプスクリプト・
  systemd の service / timer）の配置を適用する

### 3.4. 動作を確認する

```bash
ssh seiya@217.142.230.83
```

（ログイン後のシェルで）ダンプを手動で1回実行する。

```bash
sudo systemctl start mysql-backup.service
```

```bash
sudo journalctl -u mysql-backup.service --no-pager -n 20
```

```bash
systemctl list-timers mysql-backup.timer
```

- 手動実行後、ジャーナルに各データベースの「バックアップ完了」が出力されることを確認する
- タイマーの次回実行時刻が表示されることを確認する

ローカルのシェルで、バケットにオブジェクトが保管されたことを確認する。

```bash
oci os object list --namespace-name "$(terraform -chdir=terraform output -raw objectstorage_namespace)" --bucket-name "$(terraform -chdir=terraform output -raw backup_bucket_name)" --query 'data[].name'
```

失敗通知は、`mysql-backup.service` を一時的に失敗させて（`sudo systemctl start mysql-backup-notify.service`
で通知経路のみを実行して）メールが届くことで確認する。
