## 7.1. 設計方針

- **人と自動処理を分ける**: 人が操作するアカウントと、Terraform / Ansible / Operator が使う
  アカウントを分離し、自動処理に人の権限を持たせない
- **最小権限**: 自動処理のアカウントには、その処理に必要な操作のみを許可する
- **影響の大きい操作は人が行う**: ユーザー作成・権限変更など影響範囲の大きい操作は
  人が手動で実行し、自動処理の権限には含めない
- **静的な認証情報を増やさない**: サーバ上で動作する処理は、
  可能な限りインスタンス自身の身元（Instance Principal）で認証し、鍵を配置しない

## 7.2. アカウント一覧

| 層 | アカウント | 主体 | 用途 |
| -- | ---------- | ---- | ---- |
| OCI | 管理ユーザー（API キー） | 人・Terraform | インフラリソースの作成・変更 |
| OCI | 動的グループ（インスタンス） | External Secrets Operator | Vault の Secret 読み取り |
| OS | 管理ユーザー | 人・Ansible | SSH 接続と特権操作 |
| MySQL | 管理者アカウント | 人のみ | ユーザー作成・権限変更・DB 作成 |
| MySQL | 運用アカウント | 各サービスのアプリケーション | スキーマへの読み書き |

## 7.3. OCI テナンシのアカウント・権限

| 対象 | 方針 |
| ---- | ---- |
| テナンシ・コンパートメント・IAM ユーザーの設計 | 本リポジトリのスコープ外とする（[要件定義書 2.2節](../../01.requirements/REQUIREMENTS.md#22-スコープ外)） |
| Terraform の認証 | OCI の API キー方式。認証情報は Terraform Cloud の Variable（Sensitive）で保持する |
| Instance Principal | 稼働中のインスタンスを対象とする動的グループを定義し、ポリシーでコンパートメント内の Secret 読み取りのみを許可する |

動的グループとポリシーは Terraform の管理対象とし、コンソールから手動で作成しない。
許可する操作は Secret の読み取りに限定し、書き込み・削除・鍵の操作は含めない。

## 7.4. OS アカウント

| アカウント | 認証 | 権限 |
| ---------- | ---- | ---- |
| 管理ユーザー | SSH 公開鍵認証 | `sudo` による特権操作を許可する |
| `root` | 直接ログイン不可 | 管理ユーザーからの `sudo` 経由でのみ使用する |

- 管理ユーザーは cloud-init で作成し、SSH 公開鍵を登録する
- サービスごとの OS アカウントは作成しない。アプリケーションは Kubernetes 上で動作するため、
  ホスト OS に実行用アカウントを持たせない
- ユーザー・グループの詳細は [OS詳細設計書](../../03.detailed-design/OS詳細設計書.md) で扱う

## 7.5. データベースアカウント

権限を「管理者権限」と「運用権限」の 2 区分に分け、実行主体で使い分ける。

| 区分 | 認証方式 | 実行主体 | 用途 |
| ---- | -------- | -------- | ---- |
| 管理者権限 | OS の特権ユーザーによるソケット認証（パスワードを持たない） | 人が SSH 経由で手動実行 | ユーザー作成、権限変更、データベース作成 |
| 運用権限 | パスワード認証 | 各サービスのアプリケーション、および Ansible による自動処理 | スキーマへの読み書き |

- 運用権限のアカウントは個人開発プロジェクトで共有し、パスワードは OCI Vault を真実源とする
  （[6章 セキュリティ設計](../06.security/6章_基本設計書_セキュリティ設計.md)）
- 管理者権限のアカウントにはパスワードを設定せず、ネットワーク経由で使用できないようにする
- 権限の付与範囲は [MySQL詳細設計書](../../03.detailed-design/MySQL詳細設計書.md) で扱う

## 7.6. Kubernetes のアカウント

| 対象 | 方針 |
| ---- | ---- |
| クラスター管理者 | OS の管理ユーザーが保持する管理者用の資格情報で操作する |
| 各サービスの ServiceAccount | サービス側のマニフェストで定義する（本リポジトリのスコープ外） |
| External Secrets Operator | 専用の ServiceAccount を持ち、ノードの Instance Principal で OCI Vault を参照する |

クラスター内部のアクセス制御の詳細は
[Kubernetes詳細設計書](../../03.detailed-design/Kubernetes詳細設計書.md) で扱う。
