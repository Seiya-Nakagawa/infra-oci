# ホスト名・パス割り当て台帳

共有 Ingress が受け付けるホスト名と、パスプレフィックスごとの転送先を管理する。
サービスの追加・削除時は本台帳と Ansible の変数を同時に更新する。

## 割り当てルール

- 既存サービスは `technohonesty.com` 配下に、サービスごとのパスプレフィックスを割り当てて公開する
- オリジンを分離したいサービスには、`technohonesty.com` のサブドメインを割り当て、ルート（`/`）で公開する
- 同一ホスト内のパスプレフィックスは、他のサービスと重複させない
- 基盤はパスプレフィックスを除去してバックエンドへ転送する（ルート公開の場合は除去するものがなく、そのまま転送する）
- `technohonesty.com` のサブドメインは、ワイルドカードの A レコード（`*.technohonesty.com`）で
  インスタンスのパブリック IP へ解決する。DNS は外部の DNS サービスで管理し、サブドメインごとの登録は行わない
- 未割り当てのサブドメインは共有 Ingress に該当ルールがなく、404 で応答する
- サブドメインを割り当てる際は、Ansible の変数（`shared_ingress_root_hosts`）に追加する。
  TLS 証明書はホストごとに自動で再発行される（HTTP-01 のため、ワイルドカード証明書は使わない）
- 転送先の Service は、共有 Namespace に配置する

## 割り当て一覧

| ホスト名 | パスプレフィックス | 転送先 Service | ポート |
| -------- | ------------------ | -------------- | ------ |
| `technohonesty.com` | `/kakeibo` | `kakeibo-web` | 80 |
| `technohonesty.com` | `/portfolio` | `portfolio-web` | 80 |
| `skillsheet.technohonesty.com` | `/` | `portfolio-web` | 80 |

`technohonesty.com/portfolio` は、旧 URL からのリダイレクトをアプリケーション側で行うために残す。
